# 송출컴에서 끄는 동안 송출컴 배치로 움직이기 (짧은 설계)

## 왜

책상 배치가 `송출컴 1 | 게임컴 | 송출컴 2`일 때, 송출컴 1의 창을 끌고 오른쪽으로 가면 커서가 게임컴 모니터로 넘어갑니다. 넘어가는 순간 송출컴의 마우스 버튼이 풀려서 창이 송출컴 1 가장자리에 떨어집니다. 송출컴 모니터끼리 창을 옮기려면 가두기 키나 Win+Shift+화살표를 따로 써야 해서 불편합니다.

## 목표

- 송출컴에서 마우스 버튼을 누르고 있는 동안에는 **송출컴 윈도우의 디스플레이 배치**대로 움직인다(가두기 키와 같은 방식). 송출컴 1 오른쪽 끝 → 송출컴 2 왼쪽으로 바로 이어진다.
- 마지막 버튼을 떼면 원래 책상 배치로 돌아온다. 커서는 그 자리에 그대로 있다.
- 끄는 동안에는 게임컴으로 넘어가지 않는다(게임컴 쪽 "끄는 중에는 넘어가지 않기"와 짝).

## 하지 않는 것

- 책상 배치 그대로 게임컴 모니터만 건너뛰기(2번 방법).
- 게임컴에서의 동작 변경. 지금처럼 끄는 중에는 넘어가지 않는다.
- 새 설정 항목. 항상 켜져 있다.

## 정한 것

- 가두기와 같은 송출컴 배치(`_remoteOs`)를 쓰되, **끌기 때문에 켜진 상태**와 **가두기 키로 켠 상태**를 구분한다.
  - 이미 가두기 중이면 끌기는 아무것도 바꾸지 않는다(떼어도 가두기는 유지).
  - 끄는 중에 가두기 키를 누르면 가두기로 바뀐다. 버튼을 떼도 풀리지 않고, 가두기 키를 다시 눌러야 풀린다.
- 끄는 중의 빠른 전환 키는 막는다(가두기 중과 같음). 넘어가면 버튼이 풀려 창이 떨어지기 때문이다.
- 연결이 끊기거나 배치가 바뀌면 지금 가두기처럼 함께 풀린다.
- 트레이 아이콘·상태 글자는 바꾸지 않는다. 끌기는 잠깐이라 주황색(가두기)으로 바뀌면 오히려 헷갈린다.

## 만드는 사람에게 맡기는 것

- `InputRouter` 안의 이름과 구조. 단, 기존 가두기(`ToggleRemoteLock`/`EndRemoteLock`)와 같은 좌표 변환을 써야 한다.
- 테스트: 1 | 게임 | 2 배치에서 송출컴 1 끝을 버튼 누른 채 오른쪽으로 밀면 송출컴 2로 가는지, 떼면 책상 배치로 돌아오는지, 버튼 없이 밀면 지금처럼 게임컴으로 가는지, 가두기 중 끌기·끌기 중 가두기, 끌기 중 빠른 전환이 막히는지.
- README 3개 언어와 PDF에 "송출컴에서 창을 끌면 송출컴 모니터끼리 바로 옮겨져요" 한 줄.
