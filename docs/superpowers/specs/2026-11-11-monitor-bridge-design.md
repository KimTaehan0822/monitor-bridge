# Monitor Bridge — 설계 문서

작성일: 2026-11-11
상태: 초안 (사용자 승인 전)

## 1. 왜 만드나

사용자는 PC 두 대를 씁니다.

- **게임컴**: 모니터 3. 키보드와 마우스가 연결된 유일한 PC.
- **송출컴**: 모니터 1, 2. 키보드/마우스 없이 게임컴에서 조작.

지금 쓰는 인풋디렉터를 포함해 기존 도구(Mouse Without Borders, Barrier, Deskflow)는 **PC 단위**로 배치합니다. 그래서 한 PC의 모니터 사이에 다른 PC의 모니터를 끼우는 배치가 안 됩니다. 사용자는 실제 책상 위 모니터 순서대로 `1(송출) | 3(게임) | 2(송출)`처럼 배치하고, 한 PC에 모니터 세 대를 붙인 것처럼 커서가 자연스럽게 오가길 원합니다.

사용자 본인뿐 아니라 비슷한 2PC 방송 환경을 쓰는 다른 사람도 쓸 수 있어야 합니다. 그래서 처음 설정 안내가 꼭 필요합니다(§6.8).

## 2. 목표

1. **모니터 단위 자유 배치.** 두 PC의 모니터를 하나의 가상 데스크톱 위에 마음대로 놓습니다. 가로, 세로, 어긋난 배치 모두 됩니다. 커서는 이 가상 배치를 따라 움직이고, 각 PC의 윈도우 디스플레이 설정 배치는 무시합니다.
2. **입력 전달.** 게임컴(호스트)의 마우스(이동, 좌/우/가운데/사이드 버튼, 세로/가로 휠)와 키보드 입력을, 커서가 있는 PC로 보냅니다.
3. **가두기 키.** 누르면 커서가 지금 있는 PC를 벗어나지 못합니다. 다시 누르면 풀립니다. 게임할 때 쓰는 용도입니다.
4. **빠른 전환 키.** 누르면 커서가 다른 PC로 바로 넘어갑니다. 커서는 그 PC에서 마지막에 있던 자리로 갑니다.
5. **클립보드 공유 (양방향).** 글자, 이미지, 파일(단순판, §6.6).
6. **트레이 상주 프로그램 하나.** 같은 exe를 두 PC에 설치하고, 설정에서 역할(호스트/받는 쪽)을 고릅니다.

## 3. 하지 않는 것 (비목표)

- 송출컴으로 넘어간 상태에서 게임 플레이하기. FPS 시점 회전, raw input, 안티치트 대응은 하지 않습니다. 게임은 게임컴에서만 하고, 그동안 가두기 키를 켜 둡니다.
- UAC 확인창, Ctrl+Alt+Del 화면, 로그인 화면 조작. 이걸 하려면 윈도우 서비스로 만들어야 해서 제외합니다.
- 파일 완성판: 붙여넣는 순간 전송, 탐색기 진행창, 용량 무제한(§6.6).
- 드래그 앤 드롭으로 파일을 PC 간에 옮기기.
- 인터넷 너머 연결. 같은 LAN만 지원합니다.
- 윈도우 외 운영체제.
- 3대 이상 PC. v1은 호스트 1대와 받는 쪽 1대만 지원합니다. 다만 데이터 구조(모니터마다 소속 PC 표시)는 2대를 전제로 하드코딩하지 않습니다.

## 4. 실패로 보는 것 (안티 목표)

동작은 하더라도 아래 중 하나라도 생기면 실패입니다.

- 커서가 버벅이거나 늦게 따라옵니다. 같은 PC 안에서 움직일 때와 체감 차이가 나면 안 됩니다.
- 키가 눌린 채로 남습니다. PC를 넘어가거나 연결이 끊겼을 때 Ctrl/Shift/Alt가 계속 눌려 있는 경우입니다.
- 커서가 어디에도 없게 됩니다. 연결이 끊기면 커서는 반드시 게임컴 모니터로 돌아와야 합니다.
- 같은 LAN의 아무 기기나 송출컴을 조작할 수 있습니다.

## 5. 제약

- 두 PC 모두 Windows 10/11이고, 같은 LAN에 있습니다.
- 모니터마다 해상도와 배율(DPI)이 다를 수 있습니다.
- 송출컴에서 관리자 권한으로 실행한 프로그램(예: OBS)을 조작하려면, 받는 쪽 프로그램도 관리자 권한으로 실행해야 합니다(윈도우 UIPI 제한). 설정에 "관리자로 실행" 안내를 넣습니다.

## 6. 만드는 방법 (정해진 것)

### 6.1 접근법

| 방법 | 장점 | 단점 | 결과 |
|---|---|---|---|
| **A. C# .NET 8로 새로 만들기** | 윈도우 훅, SendInput, 클립보드를 쓰기 쉬움. exe 하나로 배포. 모니터 단위 배치를 처음부터 설계에 넣을 수 있음 | 윈도우 전용 | **선택** |
| B. Deskflow 고쳐 쓰기 | 연결과 클립보드 기본 기능이 이미 있음 | "PC 1대 = 화면 1개" 구조가 핵심에 박혀 있어 크게 뜯어고쳐야 함. C++ 빌드가 무거움. 윈도우 파일 공유가 사실상 없음 | 탈락 |
| C. 파이썬 | 빨리 시험해 보기 좋음 | 마우스 훅 지연으로 커서 버벅임 위험. exe 배포가 번거로움 | 탈락 |

사용자가 A를 골랐습니다.

### 6.2 프로그램 구조

- .NET 8, WinForms, 트레이 아이콘 하나.
- 같은 exe를 두 PC에 씁니다. 설정 파일(JSON, `%AppData%`)에 역할을 저장합니다.
- Per-Monitor DPI Aware v2로 실행합니다. 모든 좌표는 물리 픽셀로 다룹니다.

### 6.3 커서 위치는 호스트가 전부 결정

핵심 원리입니다. 호스트(게임컴)가 **가상 데스크톱 좌표 위의 커서 위치**를 혼자 계산합니다. 받는 쪽은 "이 모니터의 이 좌표에 커서를 둬라"라는 명령만 따릅니다.

- 호스트는 저수준 마우스 훅(`WH_MOUSE_LL`)으로 마우스 이동을 받습니다.
- **커서가 게임컴 모니터에 있을 때:** 평소대로 윈도우가 커서를 움직이게 둡니다. 다만 이동하면서 가상 배치상 다른 PC 모니터로 넘어가는 순간을 감지합니다.
- **커서가 송출컴 모니터에 있을 때:** 호스트의 실제 커서는 숨기고 한 지점에 묶어 둡니다(이동을 막고 변화량만 계산). 변화량을 가상 좌표에 더하고, 그 결과를 받는 쪽에 절대 좌표로 보냅니다. 받는 쪽은 `SendInput`(absolute, virtual desk)으로 커서를 옮깁니다.
- **송출컴 커서 숨기기:** 커서가 송출컴을 떠나면, 송출컴 커서는 그 자리에 둔 채 보이지 않게 합니다. 방송 캡처에 화살표가 잡히지 않게 하기 위해서입니다(사용자 결정). 모든 시스템 커서 모양을 투명 커서로 바꾸는 방식(`SetSystemCursor`)을 쓰고, 돌아오면 `SPI_SETCURSORS`로 원래대로 되돌립니다. 프로그램이 비정상 종료돼 커서가 안 보인 채 남는 일이 없도록, 정상 종료할 때와 프로그램이 시작할 때도 항상 되돌립니다(제 판단). 받는 쪽 프로그램은 처음 실행될 때도 커서를 숨긴 상태로 시작합니다. 호스트가 커서를 넘겨주기 전까지는 송출컴에 커서가 없는 것으로 봅니다.
- 이렇게 하면 송출컴 윈도우 설정에서 1과 2가 붙어 있어도, 커서는 가상 배치를 따라 1 → 3 → 2로 갑니다.
- 마우스 가속(포인터 정밀도)은 호스트 윈도우 설정이 적용된 값을 그대로 씁니다. 그래서 손 감각이 두 PC에서 같습니다.

### 6.4 모니터 배치

- 받는 쪽은 연결할 때와 디스플레이 구성이 바뀔 때 모니터 목록(장치 이름, 물리 해상도, 배율, 윈도우상 좌표)을 호스트에 보냅니다.
- 호스트 설정 창에 모든 모니터가 사각형으로 표시됩니다(이름 예: "송출컴 1", "게임컴 1"). 사용자가 끌어다 놓고, 가장자리끼리 달라붙습니다(snap).
- **경계 통과 규칙:** 커서가 모니터 가장자리에 닿았을 때, 가상 좌표상 바로 그 지점에 맞닿은 모니터가 있으면 그쪽으로 넘어갑니다. 없으면 윈도우처럼 그 자리에 멈춥니다.
- 크기가 다른 모니터끼리는 가상 좌표 그대로 이어집니다(비율 보정 없음). 윈도우 기본 동작과 같습니다.
- 배치는 호스트 설정 파일에 저장합니다. 받는 쪽 모니터 구성이 바뀌어서 저장된 모니터를 못 찾으면, 그 모니터를 배치에서 빼고 트레이 알림을 띄웁니다.

### 6.5 키보드와 단축키

- 호스트는 저수준 키보드 훅(`WH_KEYBOARD_LL`)을 씁니다. 커서가 송출컴에 있으면 키 입력을 막고 스캔코드로 보냅니다. 받는 쪽은 `SendInput`(스캔코드)으로 입력합니다.
- 커서가 PC를 넘어갈 때는, 떠나는 PC 쪽에 눌려 있던 키와 마우스 버튼을 모두 "뗌" 처리합니다. 연결이 끊길 때 받는 쪽도 스스로 똑같이 처리합니다.
- **가두기 키** 기본값: `Scroll Lock`. 켜지면 트레이 아이콘 모양을 바꿉니다.
- **가두기 모드에서는 마우스/키보드 훅을 완전히 해제합니다.** 게임 중 입력 지연을 없애고, 전역 훅을 문제 삼는 안티치트와 부딪힐 여지를 줄이기 위해서입니다. 가두기 해제 키는 `RegisterHotKey`로 받습니다(제 판단). 그래서 가두기는 커서가 게임컴에 있을 때만 켤 수 있습니다. 송출컴에 있을 때 누르면 무시합니다.
- **빠른 전환 키** 기본값: `Ctrl+Alt+\``(백틱).
- 두 단축키 모두 설정에서 바꿀 수 있습니다. 단축키는 호스트가 먹고 상대 PC로 보내지 않습니다.

### 6.6 클립보드

- 두 PC 모두 `AddClipboardFormatListener`로 클립보드 변화를 감지하고, 상대 PC로 바로 보냅니다(양방향). 상대가 보낸 내용을 내 클립보드에 넣을 때 생기는 변화는 다시 보내지 않습니다(무한 반복 방지).
- **글자:** 유니코드 텍스트.
- **이미지:** PNG로 압축해서 보내고, 받는 쪽에서는 비트맵과 PNG 형식을 모두 클립보드에 넣습니다.
- **파일 (단순판):**
  - 탐색기 복사(`CF_HDROP`)를 감지하면, 파일과 폴더(하위 폴더 포함)를 즉시 상대 PC로 보냅니다.
  - 받는 쪽은 `%TEMP%\MonitorBridge\<복사ID>\`에 저장하고, 전송이 끝나면 그 경로들로 `CF_HDROP`을 클립보드에 넣습니다. 그러면 사용자가 Ctrl+V로 원하는 곳에 붙여넣을 수 있습니다.
  - **용량 제한:** 기본 500MB, 설정에서 변경 가능. 넘으면 보내지 않고 트레이 알림만 띄웁니다.
  - 전송 중에 새 복사가 생기면 이전 전송을 취소합니다.
  - 임시 폴더는 최근 복사 1개만 남기고, 프로그램 시작 시에도 정리합니다.
  - 탐색기 "잘라내기"는 복사로 취급합니다(원본을 지우지 않음).
- 파일 전송이 마우스/키보드 신호를 막지 않도록, 입력 신호와 파일 데이터는 따로 처리합니다(예: 별도 연결, 또는 입력 메시지 우선 처리).

### 6.7 연결과 보안

- TCP. 받는 쪽(송출컴)이 포트에서 기다리고, 호스트가 IP:포트로 연결합니다. 자동 검색은 하지 않고 IP를 직접 입력합니다.
- 두 PC 설정에 같은 **비밀번호**를 넣습니다. 연결할 때 비밀번호를 직접 보내지 않는 인증(챌린지-응답)을 하고, 이후 통신은 비밀번호에서 만든 키로 암호화합니다. 클립보드에 비밀번호 같은 민감한 글자가 오가기 때문입니다.
- 연결이 끊기면 호스트는 커서를 게임컴 모니터로 즉시 되돌리고, 몇 초 간격으로 다시 연결을 시도합니다.

### 6.8 시작과 처음 설정

- **자동 실행:** 받는 쪽은 사용자 로그인 시 관리자 권한으로 자동 실행됩니다. 작업 스케줄러에 "로그온할 때 실행, 가장 높은 수준의 권한" 작업을 등록하고, 설정 창의 체크박스로 켜고 끕니다. 관리자 권한 앱(OBS 등)을 조작하려면 관리자 권한이 필요하고, 키보드 없는 PC에서는 UAC 창을 누를 수 없기 때문입니다. 호스트도 같은 방식으로 자동 실행할 수 있습니다.
- **로그인이 늦어도 문제없어야 합니다.** 송출컴이 자동 로그인이 아니라서 로그인까지 시간이 걸려도, 호스트는 계속 재연결을 시도하다가 받는 쪽이 뜨면 붙습니다. 그동안 커서는 게임컴에 머무릅니다. 오류창이나 재시도 포기는 없습니다.
- **로그인 화면 자체는 조작할 수 없습니다**(비목표 §3). 송출컴에 로그인 비밀번호가 걸려 있다면 자동 로그인을 켜거나, 로그인할 때만 키보드를 꽂아야 합니다. 이 내용을 안내 문서에 적습니다.
- **처음 설정 안내 문서**(README, 한국어). 초보자도 따라 할 수 있게 단계별로 씁니다.
  1. 송출컴에 **키보드와 마우스를 잠깐 꽂으세요.** 처음 설정은 송출컴에서 직접 해야 합니다.
  2. 인풋디렉터 같은 기존 프로그램을 끄세요(동시에 실행하면 입력이 꼬입니다).
  3. 두 PC에 설치하고 역할, 비밀번호, IP를 입력하세요.
  4. 받는 쪽에서 "관리자 권한으로 자동 실행"을 켜세요.
  5. 호스트 설정 창에서 모니터를 실제 책상 배치대로 끌어 놓으세요.
  6. 연결을 확인한 뒤 송출컴 키보드와 마우스를 빼세요.
  - 자주 막히는 문제: 윈도우 방화벽 허용, 로그인 비밀번호, 관리자 권한 앱 조작이 안 될 때.

## 7. 만드는 사람에게 맡기는 것

- 프로토콜의 메시지 형식, 암호화 방식의 세부(.NET 기본 제공 기능 사용).
- 설정 창 디자인 세부.
