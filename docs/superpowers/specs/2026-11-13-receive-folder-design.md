# 받은 파일을 정해 둔 폴더에 바로 저장 (짧은 설계)

## 왜
지금은 받은 파일이 숨겨진 임시 폴더(`%TEMP%\MonitorBridge`)에 먼저 들어가요. 꺼낼 방법은 클립보드뿐이라, 그 사이에 다른 것을 복사하면 일반 사용자는 파일을 찾을 수 없어요. 70GB 시험에서 실제로 이 일이 생겼어요.

## 목표
1. **받을 폴더:** 상대 PC에서 복사한 파일은 설정의 **받은 파일 저장 폴더**에 바로 저장한다.
   - 기본값은 이 PC의 다운로드 폴더다. 다운로드 위치를 D드라이브 등으로 옮겨 두었으면 옮긴 위치를 쓴다.
2. **설정 창에 경로 명시:** 다음 줄을 넣는다.
   - `받은 파일 저장 폴더 [C:\Users\…\Downloads] [찾아보기…]`
   - 그 아래 안내: "상대 PC에서 복사한 파일은 이 폴더에 저장돼요."
   - 폴더를 만들 수 없거나 쓸 수 없으면 저장 버튼 옆 오류 줄에 이유를 보여 준다.
3. **받는 중:** 받는 동안에는 저장 폴더 안의 숨김 폴더 `.MonitorBridge-받는중\<번호>`에 쓴다. 다 받으면 저장 폴더로 옮긴다. 같은 드라이브 안에서 옮기는 것이라 바로 끝나고, 디스크도 한 번만 쓴다. 반쯤 받은 파일이 다운로드 폴더에 섞여 보이지 않는다.
4. **이름이 겹칠 때:** 같은 이름이 이미 있으면 윈도우처럼 `이름 (2).확장자`, `이름 (3).확장자`로 저장한다. 폴더도 같은 방식이다.
5. **다 받으면:**
   - 알림: "다 받았어요: {이름} → {저장 폴더}. 누르면 폴더를 열어요."
   - 알림을 누르면 탐색기가 열리고 받은 파일이 선택된다.
   - 클립보드에도 저장된 위치의 파일을 넣는다. 그래서 Ctrl+V도 지금처럼 된다.
6. **취소·실패:** 받던 파일은 숨김 폴더째 지운다. 저장 폴더에는 아무것도 남지 않는다. 프로그램을 시작할 때와 새 전송이 시작될 때도 남은 숨김 폴더를 지운다.

## 하지 않을 것
- 붙여넣은 자리로 바로 받기, 화면 너머로 끌어다 놓기. 작업이 훨씬 커서 이번에는 1번 방식만 한다(사용자 선택).
- 남은 디스크 공간 확인. 별도 작업으로 남긴다.

## 방식 (제 판단)
- 설정에 `ReceiveFolder`(문자열)를 추가한다. 비어 있으면 다운로드 폴더(`SHGetKnownFolderPath(FOLDERID_Downloads)`)를 쓴다.
- 이름 겹침 처리와 옮기기는 Core의 `FileReceiver`에 두고 자동 테스트로 확인한다.
- 이전 임시 폴더(`%TEMP%\MonitorBridge`)는 시작할 때 한 번 비운다. 예전 버전이 남긴 파일을 지우기 위해서다.
- 저장 폴더를 바꿔도 다시 연결하지 않는다. 지난번 "한도만 바꾸면 연결 유지"와 같다.
